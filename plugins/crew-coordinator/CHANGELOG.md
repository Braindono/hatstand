- Item 2: ledger events `concept.linked {entry, concept, role, by}` and `concept.unlinked {entry, concept, by}`, kept in State.links (latest per entry and concept). `harness_admin op=concept_link / op=concept_unlink` (entry, concept, role about|applies|mentions). - Item 8 (d): ledger event `recall.miss {kind, ids, query, k, hits, role, note}` with kind suspect (an id request with query= whose id is not in the top 5 hits for that query), unresolved (the id is not in the corpus, with or without query=), repeat (the same agent repeats the same search, same words, filters and offset, within 10 minutes) and reported (`harness_recall miss=<what was wrong>` with the query and/or ids). Paging, refinement, a second agent and a correct id with its query do not fire. Every recall call also appends a counter line to the derived file `_harness/recall_stats.jsonl` (id requests, whether they carried query=, searches); `harness_admin op=recall_report [weeks]` prints the weekly numbers: calls, id requests and the share with query=, searches, misses by kind, and the ids and queries missed most.
